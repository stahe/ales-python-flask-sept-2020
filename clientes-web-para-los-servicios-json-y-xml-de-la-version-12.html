    31. Clientes web para los servicios jSON y XML de la versión 12

    Vamos a escribir tres aplicaciones de consola clientas de los servicios jSON y XML del servidor web que acabamos de crear. Retomamos la arquitectura cliente/servidor de la versión 11:

    Escribiremos tres scripts de consola:

    • los scripts [main] y [main3] utilizarán la capa [métier] del servidor;
    • el script [main2] utilizará la capa [métier] del cliente;

    31.1. La estructura de directorios de los scripts de los clientes

    La carpeta [http-clients/07] se obtiene inicialmente al copiar la carpeta [http-clients/06]. Posteriormente, se modifica.

    • en [1]: los datos procesados o creados por el cliente;
    • en [2], la configuración y los scripts de consola del cliente;
    • en [3], la capa [dao] del cliente;
    • en [4], la carpeta de pruebas de la capa [dao] del cliente;

    31.2.3. La fábrica de la capa [dao]

    Nuestros clientes serán multihilo. Dado que la capa [dao] está implementada mediante una clase con estado de lectura/escritura (= propiedades de lectura/escritura), cada hilo debe tener su propia capa [dao] o, de lo contrario, será necesario sincronizar el acceso a los datos compartidos entre los hilos. En este caso, optamos por la primera solución. Utilizamos una clase [ImpôtsDaoWithHttpSessionFactory] capaz de crear instancias de la capa [dao]:

    
from ImpôtsDaoWithHttpSession import ImpôtsDaoWithHttpSession

        # se almacena el parámetro
        self.__config = config

    def new_instance(self):
        # se devuelve una instancia de la capa [dao]
        return ImpôtsDaoWithHttpSession(self.__config)
